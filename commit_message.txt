🧪 [testing improvement] Add missing unit tests for extractDominantColor

🎯 **What:**
Added unit tests to `src/utils/colorExtractor.test.ts` for the `extractDominantColor` function, which relies on DOM APIs (`Image`, `HTMLCanvasElement`) not naturally available in the Node-based testing environment.

📊 **Coverage:**
The tests now mock `global.Image` and `document.createElement('canvas')` and cover the following paths:
- Fallback color assignment on missing `imageUrl` input
- Fallback color when image `onerror` gets triggered
- Fallback when a `canvas` context is unavailable (null)
- Fallback when image processing takes longer than the expected timeout (1200ms)
- Successful data pixel scanning to fetch a vibrant dominant color
- Local cache lookup logic to avoid creating a new `canvas` instance repeatedly
- `try/catch` rescue to a fallback color if `ctx.getImageData` throws an exception

✨ **Result:**
Significant improvement in test coverage for color extraction UI features, protecting DOM fallback edge cases, avoiding potential app crashes, and offering higher confidence for future refactors in metadata color styling.
